# 少額・短期売買の実験

元金5万円で、暗号資産とレバレッジ型ETFの短期売買を3か月試し、「買って放置」と比べる実験。
儲けることより、検証と運用の技術を身につけることが目的。

## 運用ルール

| 項目 | 決定 |
|---|---|
| 運用期間 | 2026/11/24〜2027/2/26 |
| 資金 | 枠A 1万円、枠B 1万円、残り3万円は銀行口座 |
| 追加入金 | 期間中はしない |
| 打ち切り | 枠が6,000円を割ったら、その枠は停止 |
| 禁止 | レバレッジ取引、信用取引、FX、先物（損失が入金額を超えうるもの） |

### 枠A：暗号資産（bitbank、ボットで自動）

- BTC/JPY に5,000円、ETH/JPY に5,000円
- 4時間足。終値が直近20本の高値を上抜けたら次の足で全額買い、直近10本の安値を下抜けたら全部売る

### 枠B：レバレッジ型ETF（証券口座、手動）

- 2869 iFreeETF NASDAQ100レバレッジ（予備：1579 日経平均ブル2倍）
- 日足。終値が直近10日の高値を上抜けたら翌営業日の寄付で買い、直近5日の安値を下抜けたら翌営業日の寄付で売る

### 判定（2027/2/27）

比較対象は、開始日に同額を買って放置した場合（枠AはBTC、枠Bは同じETF）。
取引回数の基準は枠Aが5回、枠Bが2回（売って1回と数える）。

1. 放置を上回り、取引回数の基準を満たした枠に3万円を入れる
2. 両方が満たしたら1万5千円ずつ
3. 放置は上回ったが取引回数が足りない枠は、追加せず3か月延長
4. 両方とも放置に負けたら追加せず、ルールを見直す

## バックテスト結果（2026/11/16 時点）

費用：手数料は bitbank の公開APIで確認したテイカー料率（BTC 0.10%、ETH 0.12%）。ずれは仮定で、暗号資産0.05%、ETF 0.1%。ETFの手数料は0と仮定。

### 全期間

| 対象 | 期間 | 戦略 | 放置 | 戦略の最大下落 | 放置の最大下落 | 取引回数 | 勝率 |
|---|---|---|---|---|---|---|---|
| BTC/JPY | 2021/1〜 | +105.4% | +233.3% | -43.4% | -70.6% | 177 | 37% |
| ETH/JPY | 2021/1〜 | -14.8% | +281.4% | -68.2% | -77.4% | 196 | 31% |
| 2869 | 2022/11〜 | +28.5% | +204.4% | -37.5% | -45.7% | 38 | 32% |
| 1579 | 2021/11〜 | -16.3% | +212.3% | -31.1% | -45.9% | 45 | 38% |

### 13週間だけ運用した場合（開始日を1週間ずつずらして繰り返し）

| | BTC/JPY | ETH/JPY | 2869 | 1579 |
|---|---|---|---|---|
| 戦略の中央値 | -0.0% | -2.5% | +0.2% | -1.5% |
| 放置の中央値 | +3.2% | +6.5% | +8.0% | +5.8% |
| 戦略の最悪 | -31.2% | -46.8% | -16.8% | -17.3% |
| 放置の最悪 | -48.3% | -65.7% | -28.9% | -33.7% |
| 放置に勝った割合 | 48% | 44% | 29% | 24% |
| 取引回数の中央値 | 7 | 8 | 2 | 2 |
| 取引10回以上の割合 | 5% | 14% | 0% | 0% |

読み取れること：

- どの対象でも、全期間では放置に大きく負けている。上昇相場だったので、途中で降りるルールは不利だった
- 下落幅は放置より小さい。このルールの価値は「増やす」より「大負けを減らす」側にある
- 当初の基準「取引10回以上」は3か月ではほぼ満たせない（ETFは0%）ので、枠A 5回・枠B 2回に下げた

## 使い方

```bash
pip install -r requirements.txt
python -m pytest -q
python -m backtest.run            # バックテスト（2回目以降は data/ のキャッシュを使う）
python -m backtest.run --refresh  # 価格データを取り直す
python -m bot.run                 # 枠A の仮想売買を1回分進める
python -m bot.etf_signal          # 枠B の「明日やること」を出す
```

## 自動実行（GitHub Actions）

`.github/workflows/bot.yml` が4時間ごとに動き、結果を `records/` にコミットする。

- 何もしなくても仮想売買（注文は出さない）と枠Bのシグナル更新が動く
- 実弾にするには、リポジトリの Settings → Secrets and variables → Actions で次を設定する
  1. Secrets に `BITBANK_API_KEY` と `BITBANK_API_SECRET` を登録（出金権限なしのキー）
  2. Variables に `LIVE_TRADING` = `true` を登録
- 止めるときは `LIVE_TRADING` を消す。保有中の分は自動では売られないので、取引所の画面で売る

## 記録（`records/`）

| ファイル | 内容 |
|---|---|
| `crypto_trades_paper.csv` / `crypto_trades_live.csv` | 枠A の取引ごとの記録 |
| `crypto_equity_paper.csv` / `crypto_equity_live.csv` | 枠A の評価額と、放置した場合の評価額 |
| `crypto_state_*.json` | ボットの状態（現金、保有数量、処理済みの足） |
| `etf_signal.md` | 枠B の「明日やること」 |
| `etf_trades.csv` | 枠B の取引記録（手で追記する） |

## 構成

- `backtest/strategy.py`：売買ルールと損益計算（ボットからも使う）
- `backtest/data.py`：価格データの取得（bitbank 公開API、Yahoo Finance）
- `backtest/run.py`：バックテストの実行
- `bot/trader.py`：枠A の売買判断、上限・停止の安全策、記録
- `bot/bitbank.py`：bitbank の API クライアント
- `bot/run.py`：枠A の実行（仮想売買／実弾）
- `bot/etf_signal.py`：枠B のシグナル確認

## 秘密情報

APIキーはリポジトリに入れない。`.env` などに置き、出金権限なしで発行する。
